# 데브컨테이너 AI 하네스 반영 계획

- 작성일: 2026-06-16
- 상태: 초본 (실행 전 확정 대기)
- 기준 비교 대상: `workSpace/ai-review/` (AI 하네스 데브컨테이너 설계·템플릿 문서 모음)
- 권위 표준: `standards/devcontainer/devcontainer-standards.md`

## 배경

`workSpace/ai-review`는 `k8s.Gssi.AiChatbot.Web`의 데브컨테이너를 분석해, **리빌드되어도
Claude/Codex(CLI+Extension)와 superpowers/gstack 스킬이 항상 살아있는 드롭인 AI 하네스**로
재구성한 설계 문서 모음이다. 이를 기준으로 본 하네스의 두 데브컨테이너
(① 유지보수용 `.devcontainer/`, ② 배포 템플릿 `templates/devcontainer/`)의 AI 부분을 비교한 결과를
반영하기 위한 계획이다.

ai-review의 핵심 명제: **리빌드 생존 = (A) named volume 상태 보존 + (B) postStart 멱등 재설치**,
그리고 superpowers + gstack(browse/Chromium) 풀스택 스킬.

## 진단 요약

### 부족한 점 (harness < ai-review)

- **G1. postStart 멱등 안전망 부재** — 스킬 설치가 post-create(1회)에만 있고 post-start는 echo만 함.
  볼륨 초기화 후 리빌드 없이 재기동하면 스킬이 복구되지 않음.
- **G2. gstack + browse(Playwright Chromium) 전무** — superpowers만 있고 gstack/chromium/playwright 없음.
- **G3. `.claude.json` 보존이 유지보수 컨테이너에 없음** — 배포 템플릿은 처리하나(`.ai-state/claude`),
  유지보수 컨테이너는 `.claude`/`.codex`만 마운트 → 리빌드 시 온보딩/프로젝트 신뢰 상태 소실.
- **G4. 배포 템플릿엔 스킬 설치가 없음** — 의도적 제외(아래 D4에서 유지).
- **G5. 스킬 repo 버전 고정 옵션 없음** — `--depth 1` HEAD 클론 고정, SHA 핀 불가.

### harness가 앞선 점 (유지)

- Codex `multi_agent = true` 자동 설정 (ai-review 템플릿엔 없음).
- AI CLI를 이미지 레이어에 baked (`javascript-node` base) → 캐싱·재현성 면에서 우수.
- 배포 템플릿의 `aiStateVolumePrefix` 자동 격리 (ai-review `PROJECT_SLUG`와 동등).

## 결정 사항

- **D1 = (b) 공식 Dev Container Feature 전환** (최신 + 자동 업데이트). 핀+`DISABLE_AUTOUPDATER`는
  선택 경로로만. → 본 하네스가 갖고 있던 "핀했지만 autoupdater 미차단 → 드리프트" 안티패턴(ai-review H1) 해소.
- **D4 = 세분화** — 배포 템플릿에 스킬 **콘텐츠/자동설치 스크립트는 넣지 않는다**(기존 D4 유지).
  다만 **"superpowers/gstack을 이런 방식으로 설치하라"는 설치 규칙은 배포 규칙 문서로 포함한다**(D6 신설).
- 나머지 전부 적용: G1·G2·G3·G5 + D2(gstack)·D3(postStart)·D5(egress).

- **D6 = 배포 규칙 문서 (신설)** — 타깃 프로젝트가 데브컨테이너를 설정할 때 superpowers/gstack을
  유지보수 컨테이너와 동일한 방식으로 설치할 수 있도록 **설치 절차·규칙을 `devcontainer` 표준 문서에 섹션으로 추가**한다.
  - 전달 채널 = 배포 규칙 문서(확정): `standards/devcontainer/devcontainer-standards.md` → `pah install` 시
    프로젝트 `docs/devcontainer/...` + `AGENTS.md`/`CLAUDE.md` 관리블록 + `.cursor` rule로 자동 전파.
  - 새 도메인·새 stub·테스트 추가 불필요(기존 `devcontainer` 도메인 표준에 섹션만 추가).
  - 스킬 콘텐츠/자동설치 스크립트는 **여전히 미포함** — 넣는 것은 "설치 방법 규칙"뿐. 실행 여부는 프로젝트가 결정.

### 스코프 확정

- **D1(b) 적용 범위**: 유지보수 컨테이너 + 배포 템플릿 **둘 다** (테스트 `tests/test_pah.sh`도 함께 수정).
- **D5 egress 하드닝 범위**: **유지보수 컨테이너만 기본 ON**. 배포 템플릿엔 `init-firewall.sh`를
  동봉하되 기본 비활성 + README에 켜는 법 안내.

## A. 유지보수 컨테이너 `.devcontainer/`

| # | 파일 | 변경 |
| --- | --- | --- |
| A1 | `devcontainer.json` | `features`에 `ghcr.io/anthropics/devcontainer-features/claude-code:1.0` 추가 / `extensions`에서 `anthropic.claude-code` 제거(Feature가 자동 추가) |
| A2 | `Dockerfile` | npm 설치에서 `@anthropic-ai/claude-code` + `claude --version` 제거(Codex 핀 유지) / apt에 `chromium` 추가 |
| A3 | `docker-compose.dev.yml` | build arg `CLAUDE_CODE_VERSION` 제거 / `pah-claude-json:/home/vscode/.ai-state/claude` 볼륨 추가 / `cap_add: [NET_ADMIN, NET_RAW]` |
| A4 | `.env.example`, `initializeCommand.sh` | `CLAUDE_CODE_VERSION` 제거(Codex만 유지) |
| A5 | `versions.env` (신규) | `BUN_VERSION`, `SUPERPOWERS_REPO/REF/MARKETPLACE`, `GSTACK_REPO/REF` (G5 SHA 핀 옵션; 비우면 HEAD) |
| A6 | `ensure-ai-skills.sh` (install-superpowers.sh 확장·개명) | 기존 superpowers + bun + gstack(claude/codex) clone+setup + chromium `launch()` 헬스체크 오케스트레이터. `ensure_command` graceful degrade 유지 |
| A7 | `ensure-ai-volume-permissions.sh` | chown 대상에 `/home/vscode/.ai-state` 추가 |
| A8 | `post-create.sh` | `.claude.json` → `.ai-state/claude/.claude.json` 심링크(G3) + `ensure-ai-skills.sh` 호출 |
| A9 | `post-start.sh` | `ensure-ai-skills.sh`(멱등 안전망 G1) → 그 다음 `init-firewall.sh` |
| A10 | `init-firewall.sh` (신규) | egress allowlist(npm/github/anthropic/playwright CDN). 스킬 설치 후 마지막에 적용해 첫 기동 설치 안 깨지게 |
| A11 | `README.md` | Feature 전환·gstack·`.claude.json`·egress 반영 |

> 순서 주의: 첫 기동 시 스킬 설치(github/npm/playwright CDN 접근)가 끝난 **뒤** 방화벽을 올린다.
> `post-start.sh`에서 `ensure-ai-skills.sh` → `init-firewall.sh` 순.

## B. 표준 문서 (D1b 정합)

- `standards/devcontainer/devcontainer-standards.md` 개정:
  - "AI CLI Installation" / "Version Pinning"을 **기본 = 공식 Feature(최신+자동업데이트),
    핀 + `DISABLE_AUTOUPDATER` = 선택 경로**로 변경. Codex는 공식 feature가 없어 핀 유지.
  - **"AI Skill Setup (superpowers / gstack)" 섹션 신설 (D6)** — 설치 절차·규칙 문서화:
    superpowers(Claude 플러그인 marketplace add/install, Codex skills 심링크 + `multi_agent=true`),
    gstack(clone + `setup --host claude/codex` + bun + chromium `launch()` 헬스체크),
    멱등·graceful degrade 원칙, 버전 고정(`*_REF`) 옵션. 유지보수 컨테이너 스크립트가 참조 구현.
- `*.ko.md` 번역본 동기화 (사람용, 권위 아님).

> 모노레포 루트 `docs/devcontainer/*`와 타깃 프로젝트 `docs/*`는 `pah install`이 복사하는 사본이므로
> **원본(`standards/`)만 수정**한다.

## C. 배포 템플릿 + 테스트 (D1b 적용, 스킬·egress 미활성)

- `templates/devcontainer/devcontainer.json` / `Dockerfile` / `.env.example` /
  `commands/initializeCommand.sh` — Claude Code를 Feature로 전환, `CLAUDE_CODE_VERSION` 제거.
- `init-firewall.sh` 동봉하되 미연결(기본 OFF) + README에 켜는 법 안내 (D5 옵션1).
- 스킬 **콘텐츠/자동설치 스크립트는 미포함 유지** (D4).
- **스킬 설치 규칙(D6)은 B의 표준 문서 개정으로 자동 전파** — 템플릿 자체엔 별도 파일 추가 없음.
  `templates/devcontainer/README.md`에 표준 문서를 가리키는 짧은 포인터만 추가(선택).
- `tests/test_pah.sh` — `CLAUDE_CODE_VERSION=2.1.170` 검증(162행 등) 갱신, Feature 존재 검증 추가.

## D. 검증

- `docker compose -f .devcontainer/docker-compose.dev.yml config`
- Reopen → Rebuild 2회 후:
  - `claude --version`, `codex --version`
  - `claude plugin list | grep superpowers`
  - gstack `browse` 바이너리 존재 / `chromium.launch()` 헬스체크
  - `.claude.json` 심링크 확인
  - egress 차단(허용 도메인 외 차단) 확인
- `bash tests/test_pah.sh` 통과

> egress 방화벽은 컨테이너 내부 iptables/ipset을 다루므로 실제 동작 검증은 Rebuild 환경에서 직접 확인 필요.
