# Final Implementation Design: Devcontainer AI Harness Alignment

Date: 2026-06-16
Status: Final implementation design
Source draft: `dev-docs/개선사항/설계/초본/2026-06-16-데브컨테이너-ai-하네스-반영-계획.md`
Authoritative target standard: `standards/devcontainer/devcontainer-standards.md`

## Implementation Goal

Implement the selected `ai-review` decisions in Personal-Agent-Harness without turning the
distributed devcontainer template into a bundled skill installer.

The implementation has four concrete outcomes:

1. Claude Code is installed through the official devcontainer Feature in both devcontainers.
2. The maintainer devcontainer keeps AI state across rebuilds and repairs skills on every start.
3. The maintainer devcontainer installs superpowers plus gstack/browse with optional repo ref pins.
4. The distributed template receives only the Claude Feature change, optional firewall file, and
   standards documentation for skill setup.

## Non-Goals

- Do not add a new rule domain.
- Do not add superpowers or gstack auto-install scripts to `templates/devcontainer/`.
- Do not edit generated target-project copies under `docs/devcontainer/`; edit `standards/` only.
- Do not merge to `main` or push as part of this implementation.

Add `.devcontainer/versions.env`:

```bash
BUN_VERSION=1.2.17
SUPERPOWERS_REPO=https://github.com/obra/superpowers.git
SUPERPOWERS_REF=
SUPERPOWERS_MARKETPLACE=obra/superpowers-marketplace
GSTACK_REPO=https://github.com/briangwaltney/gstack.git
GSTACK_REF=
```

Rules:

- Empty `*_REF` means use the default branch HEAD.
- Non-empty `*_REF` means checkout exactly that tag, branch, or SHA after clone/fetch.
- `versions.env` is committed defaults, not a secret file.

Rename `.devcontainer/commands/install-superpowers.sh` to
`.devcontainer/commands/ensure-ai-skills.sh`.

The new script must source `versions.env` and implement these units:

- `ensure_ai_volume_permissions`: call existing `ensure-ai-volume-permissions.sh`.
- `ensure_bun`: install or verify Bun at `BUN_VERSION`; skip gstack setup with a warning if Bun cannot be installed.
- `ensure_repo <url> <path> <ref>`: clone if missing, fetch if present, checkout `ref` when set.
- `ensure_claude_superpowers`: use `SUPERPOWERS_MARKETPLACE`; skip with a warning when `claude` is unavailable.
- `ensure_codex_superpowers`: keep current reliable symlink path:
  `~/.agents/skills/superpowers -> ~/.codex/superpowers/skills`; attempt Codex plugin install only when available.
- `ensure_codex_multi_agent`: preserve current `[features] multi_agent = true` behavior.
- `ensure_gstack`: clone/fetch `GSTACK_REPO` to `~/.codex/gstack`, checkout `GSTACK_REF` when set, then run:

```bash
bun install
bun run setup --host claude
bun run setup --host codex
```

- `verify_browse_chromium`: run a small Playwright/Chromium launch check; warn rather than fail the whole container when it fails.

Failure policy:

- Missing `claude`, missing `codex`, temporary marketplace unavailability, or gstack browser health failure should print `WARN:` and continue.
- Shell syntax errors, missing script files, or permission repair failures should fail fast.

Edit `.devcontainer/commands/ensure-ai-volume-permissions.sh`:

- Include `/home/vscode/.ai-state` in the ownership repair loop.

Edit `.devcontainer/commands/post-create.sh`:

```bash

```

- Replace the call to `install-superpowers.sh` with `ensure-ai-skills.sh`.
- Update the status section to mention gstack/browse health.

Edit `.devcontainer/commands/post-start.sh`:

- Replace the echo-only script with:

```bash
#!/usr/bin/env bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
"$SCRIPT_DIR/ensure-ai-skills.sh"
"$SCRIPT_DIR/init-firewall.sh"
```

Add `.devcontainer/commands/init-firewall.sh`:

- Must be idempotent.
- If `iptables` or `ipset` is missing, print `WARN:` and exit 0.
- Allow loopback, established connections, DNS, GitHub, npm registry, Anthropic endpoints, OpenAI endpoints,
  Bun downloads, and Playwright/Chromium downloads needed by first setup and later updates.
- Apply only after `ensure-ai-skills.sh`, because first setup needs outbound package and browser downloads.

Edit `.devcontainer/README.md`:

- Replace pinned Claude npm install language with official Feature language.
- Document named volume preservation for `.claude`, `.claude.json`, and `.codex`.
- Document `ensure-ai-skills.sh`, `versions.env`, gstack/browse, and the default-on maintainer firewall.
- Update troubleshooting commands to use `ensure-ai-skills.sh`.

### 2. Devcontainer Standard Documents

Edit `standards/devcontainer/devcontainer-standards.md` first, then sync
`standards/devcontainer/devcontainer-standards.ko.md`.

Required semantic changes:

- Final Consensus:
  - Replace "Install AI CLIs in the Dockerfile, with explicit pinned versions" with:
    "Use official devcontainer Features for AI CLIs when available; otherwise install pinned CLIs in the Dockerfile."
- Version Pinning:
  - Remove `CLAUDE_CODE_VERSION` from the required pins.
  - Keep `CODEX_CLI_VERSION`.
  - State that Claude Code defaults to the official Feature's update channel.
  - If a project chooses npm-pinned Claude Code instead, it must also disable Claude's autoupdater and document the exception.
- AI CLI Installation:
  - Claude Code default: official Feature.
  - Codex default: Dockerfile npm install with `CODEX_CLI_VERSION`.
  - Explicitly forbid installing Claude through both Feature and Dockerfile.
- Lifecycle Commands:
  - `post-start.sh` may run lightweight idempotent AI skill repair when AI state is volume-backed.
- Add section `AI Skill Setup (superpowers / gstack)`:
  - Explain that distributed templates should document this setup but not automatically install skills unless the project opts in.
  - Define the required principles: named-volume state, idempotent post-start repair, optional repo ref pins, graceful degradation.
  - Use the maintainer `.devcontainer/commands/ensure-ai-skills.sh` as the reference implementation.

Do not change `templates/stubs/agent-blocks/devcontainer.md` unless the standard path or managed block wording needs to change. The existing stub already points agents to `docs/devcontainer/devcontainer-standards.md`.

## Required Verification

Run these from the repository root after implementation:

```bash
bash tests/test_pah.sh
git diff --check
```

Also run static devcontainer config checks when Docker is available:

```bash
docker compose -f .devcontainer/docker-compose.dev.yml config
```

Manual rebuild verification for the maintainer container:

```bash
claude --version
codex --version
test -L ~/.claude.json
claude plugin list | grep superpowers
test -e ~/.agents/skills/superpowers
test -d ~/.codex/gstack
```

For gstack/browse, use the health check implemented in `ensure-ai-skills.sh`; it should launch Chromium
successfully or print a clear `WARN:` with the failing command.
