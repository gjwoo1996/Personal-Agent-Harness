# Final Design: Devcontainer AI Skill Sharing

Date: 2026-06-10

## Scope

This design defines how Personal-Agent-Harness installs and connects the `superpowers` and `gstack` skills for AI tools running inside the devcontainer.

The skills are devcontainer environment assets, not PAH rule domains and not a separate `pah install --components skills` component.

## Goals

- Install `superpowers` and `gstack` inside the devcontainer in an idempotent way.
- Let Codex and Claude read the same skill sources from a stable container path.
- Connect only `gstack` to Cursor through `.cursor/rules/gstack-skill.mdc`.
- Keep the existing `rules` and `hooks` installation model separate from AI skill bootstrap.
- Let `pah verify` and `tests/test_pah.sh` validate the devcontainer skill scaffold.

## Non-Goals

- Do not install skills to `.harness/skills/<skill-id>/` in the target project.
- Do not add a new `skills` component to `pah install --components`.
- Do not depend on private or unstable Codex or Claude native plugin APIs.
- Do not connect `superpowers` to Cursor.
- Do not parse or execute the internal skill behavior in PAH.
- Do not modify target project files during `npm install` or package download.

## Core Model

Skills are installed as part of the devcontainer AI bootstrap.

```text
pah init .
  -> setup.sh
  -> pah install . --components rules,hooks

pah install . --components devcontainer
  -> scaffold .devcontainer/
  -> scaffold .devcontainer/ai-skills/
  -> merge Codex/Claude devcontainer AI skill blocks
  -> install .cursor/rules/gstack-skill.mdc

devcontainer post-create
  -> run .devcontainer/ai-skills/install-ai-skills.sh
  -> install skills into /home/vscode/.local/share/pah/ai-skills/
```

The stable container skill paths are:

```text
/home/vscode/.local/share/pah/ai-skills/superpowers/
/home/vscode/.local/share/pah/ai-skills/gstack/
```

AI login tokens, conversations, and config remain separate state managed by the devcontainer state storage strategy. Skill files are reproducible bootstrap output, not state.

## Skill Metadata

Each skill snapshot must include `metadata.json`.

Required fields:

| Field | Meaning |
| --- | --- |
| `id` | Skill ID. Must match the directory name. |
| `source` | Canonical source URL for the vendored snapshot. |
| `source_ref` | Source commit, tag, release, or equivalent update reference. |
| `license` | Redistributable license identifier or bundled license file path. |
| `vendored_at` | Date the snapshot was added to PAH. |
| `notes` | Extra update or install notes. |

`gstack` source and license must be confirmed before implementation. If they are not confirmed, the real skill snapshot must not be shipped.

## Installer Behavior

`.devcontainer/ai-skills/install-ai-skills.sh` must:

- Install into `/home/vscode/.local/share/pah/ai-skills/`.
- Be safe to run multiple times.
- Skip work when the installed version already matches the scaffolded version.
- Copy into a temporary directory before replacing the final skill directory.
- Print clear errors that identify the failing skill and step.
- Never store login tokens, conversation history, or AI config.

`templates/devcontainer/commands/post-create.sh` must call:

```bash
bash .devcontainer/ai-skills/install-ai-skills.sh
```

## AI Connections

### Codex

`pah install <target> --components devcontainer` must merge this managed block into `AGENTS.md`:

```text
<!-- pah:devcontainer-ai-skills:start -->
When working inside the PAH devcontainer, read:
- /home/vscode/.local/share/pah/ai-skills/superpowers/SKILL.md
- /home/vscode/.local/share/pah/ai-skills/gstack/SKILL.md
<!-- pah:devcontainer-ai-skills:end -->
```

Codex native plugin or skill directories are out of scope for the first implementation.

### Claude

`pah install <target> --components devcontainer` must merge an equivalent managed block into `CLAUDE.md`.

Claude Code native skill directory installation is out of scope for the first implementation.

### Cursor

`pah install <target> --components devcontainer` must install:

```text
.cursor/rules/gstack-skill.mdc
```

The rule must contain a short description of `gstack` and point to:

```text
/home/vscode/.local/share/pah/ai-skills/gstack/SKILL.md
```

PAH must not create `.cursor/rules/superpowers-skill.mdc`.

## Managed Blocks

Codex and Claude use one devcontainer AI skill block:

```text
<!-- pah:devcontainer-ai-skills:start -->
...
<!-- pah:devcontainer-ai-skills:end -->
```

The installer must preserve content outside managed blocks. It must fail before writing if the target file contains broken or duplicate `pah:devcontainer-ai-skills` markers.

## Manifest

`.harness/manifest.json` records only target project files. It must not record container-internal `/home/vscode/...` paths.

When the `devcontainer` component is installed, the manifest should include the devcontainer AI skill scaffold files under the existing `devcontainer` manifest section. Do not create a separate `skills` manifest section.

Files to include include:

```text
.devcontainer/ai-skills/install-ai-skills.sh
.devcontainer/ai-skills/skills-manifest.json
.devcontainer/ai-skills/superpowers/README.md
.devcontainer/ai-skills/superpowers/SKILL.md
.devcontainer/ai-skills/superpowers/metadata.json
.devcontainer/ai-skills/gstack/README.md
.devcontainer/ai-skills/gstack/SKILL.md
.devcontainer/ai-skills/gstack/metadata.json
.cursor/rules/gstack-skill.mdc
```

## Verification

`pah verify` validates devcontainer AI skill scaffold files only when the manifest contains devcontainer outputs.

Required checks:

- `.devcontainer/ai-skills/install-ai-skills.sh` exists and is executable.
- `.devcontainer/ai-skills/skills-manifest.json` exists.
- Each skill has `README.md`, `SKILL.md`, and `metadata.json`.
- Each `metadata.json` has `id`, `source`, `source_ref`, `license`, and `vendored_at`.
- `AGENTS.md` and `CLAUDE.md` contain the expected `pah:devcontainer-ai-skills` managed block.
- `.cursor/rules/gstack-skill.mdc` exists and references `/home/vscode/.local/share/pah/ai-skills/gstack/SKILL.md`.
- `.cursor/rules/superpowers-skill.mdc` does not exist.
- Manifest hashes match actual scaffold files.

Container-internal install results are verified with a devcontainer smoke command, not by default `pah verify`:

```bash
bash .devcontainer/ai-skills/install-ai-skills.sh
test -f /home/vscode/.local/share/pah/ai-skills/superpowers/SKILL.md
test -f /home/vscode/.local/share/pah/ai-skills/gstack/SKILL.md
```

## Test Plan

Add coverage to `tests/test_pah.sh` for:

- `pah install <target> --components devcontainer` creates `.devcontainer/ai-skills/`.
- `install-ai-skills.sh` is executable.
- `superpowers` and `gstack` scaffold files include `README.md`, `SKILL.md`, and `metadata.json`.
- Missing required metadata fields cause install or verify to fail.
- `post-create.sh` calls `install-ai-skills.sh`.
- `AGENTS.md` and `CLAUDE.md` receive the devcontainer AI skill managed block.
- `.cursor/rules/gstack-skill.mdc` is created.
- `.cursor/rules/superpowers-skill.mdc` is not created.
- `pah verify <target>` passes for a valid devcontainer AI skill scaffold.
- Re-running `pah install <target> --components devcontainer` does not duplicate managed blocks.
- Broken `pah:devcontainer-ai-skills` markers cause install to fail without overwriting user content.
- `pah install <target> --components rules,hooks` does not create `.devcontainer/ai-skills/`.
- `npm install` or package download alone does not create target project files.

## Implementation Steps

1. Add `templates/devcontainer/ai-skills/`.
2. Add vendored `superpowers` and `gstack` snapshots with `README.md`, `SKILL.md`, and `metadata.json`.
3. Add `templates/devcontainer/ai-skills/install-ai-skills.sh`.
4. Update `templates/devcontainer/commands/post-create.sh` to run the installer.
5. Add Codex and Claude managed block stubs for devcontainer AI skills.
6. Add the Cursor `gstack-skill.mdc` stub.
7. Update `bin/pah` devcontainer install flow to copy the AI skill scaffold, merge managed blocks, and install the Cursor rule.
8. Update `pah verify` for devcontainer AI skill scaffold validation.
9. Add failing tests first in `tests/test_pah.sh`, then implement until they pass.
10. Update `docs/usage.md`, `docs/reference.md`, and `docs/how-it-works.md`.
11. Run `bash tests/test_pah.sh` and `git diff --check`.

## Risks And Mitigations

| Risk | Mitigation |
| --- | --- |
| Skills and rule domains become mixed | Do not add a `skills` component. Keep skills under the devcontainer scaffold. |
| Container-internal files are incorrectly tracked by manifest | Track only target project scaffold files. Use smoke commands for container checks. |
| Skills disappear after rebuild | Re-run the idempotent installer from `post-create.sh`. |
| AI state and skill files become mixed | Keep login/config state in named volumes and skill files in reproducible bootstrap output. |
| Cursor reads too much context | Connect only `gstack` to Cursor and keep the rule short. |
| Vendored snapshots drift from upstream | Record source/ref/license/vendored_at in metadata and update through explicit commits. |
| Existing projects receive unexpected files | Create AI skill scaffold only when installing the `devcontainer` component. |
