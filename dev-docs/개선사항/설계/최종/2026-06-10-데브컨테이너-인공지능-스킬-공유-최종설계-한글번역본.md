# 최종 설계: Devcontainer AI 스킬 공유

작성일: 2026-06-10

## 범위

이 설계는 Personal-Agent-Harness가 devcontainer 안에서 실행되는 AI 도구를 위해 `superpowers`, `gstack` 스킬을 설치하고 연결하는 방식을 정의한다.

스킬은 devcontainer 환경 구성 요소다. PAH 규칙 도메인이 아니며, 별도의 `pah install --components skills` 컴포넌트도 아니다.

## 목표

- `superpowers`, `gstack`을 devcontainer 안에 idempotent하게 설치한다.
- Codex와 Claude가 안정적인 컨테이너 내부 경로에서 같은 스킬 원본을 읽게 한다.
- Cursor에는 `.cursor/rules/gstack-skill.mdc`를 통해 `gstack`만 연결한다.
- 기존 `rules`, `hooks` 설치 모델과 AI 스킬 bootstrap을 분리한다.
- `pah verify`와 `tests/test_pah.sh`가 devcontainer 스킬 scaffold를 검증하게 한다.

## 비목표

- 대상 프로젝트의 `.harness/skills/<skill-id>/`에 스킬을 설치하지 않는다.
- `pah install --components`에 새 `skills` 컴포넌트를 추가하지 않는다.
- Codex 또는 Claude의 비공개/불안정한 native plugin API에 의존하지 않는다.
- `superpowers`를 Cursor에 연결하지 않는다.
- PAH가 스킬 내부 동작을 해석하거나 실행하지 않는다.
- `npm install` 또는 패키지 다운로드 시점에 대상 프로젝트 파일을 수정하지 않는다.

## 핵심 모델

스킬은 devcontainer AI bootstrap의 일부로 설치한다.

```text
pah init .
  -> setup.sh
  -> pah install . --components rules,hooks

pah install . --components devcontainer
  -> .devcontainer/ scaffold
  -> .devcontainer/ai-skills/ scaffold
  -> Codex/Claude devcontainer AI skill block 병합
  -> .cursor/rules/gstack-skill.mdc 설치

devcontainer post-create
  -> .devcontainer/ai-skills/install-ai-skills.sh 실행
  -> /home/vscode/.local/share/pah/ai-skills/에 스킬 설치
```

안정적인 컨테이너 내부 스킬 경로는 다음과 같다.

```text
/home/vscode/.local/share/pah/ai-skills/superpowers/
/home/vscode/.local/share/pah/ai-skills/gstack/
```

AI 로그인 토큰, 대화 내역, 설정은 devcontainer state 저장 전략이 관리하는 별도 상태다. 스킬 파일은 재생성 가능한 bootstrap 산출물이며 state가 아니다.

## 원본 구조

PAH 저장소 원본:

```text
templates/devcontainer/ai-skills/
├── install-ai-skills.sh
├── skills-manifest.json
├── superpowers/
│   ├── README.md
│   ├── SKILL.md
│   └── metadata.json
└── gstack/
    ├── README.md
    ├── SKILL.md
    └── metadata.json
```

대상 프로젝트 scaffold:

```text
.devcontainer/ai-skills/
├── install-ai-skills.sh
├── skills-manifest.json
├── superpowers/
│   ├── README.md
│   ├── SKILL.md
│   └── metadata.json
└── gstack/
    ├── README.md
    ├── SKILL.md
    └── metadata.json
```

컨테이너 내부 설치 결과:

```text
/home/vscode/.local/share/pah/ai-skills/
├── superpowers/
│   ├── README.md
│   ├── SKILL.md
│   └── metadata.json
└── gstack/
    ├── README.md
    ├── SKILL.md
    └── metadata.json
```

## 스킬 메타데이터

각 스킬 snapshot은 `metadata.json`을 포함해야 한다.

필수 필드:

| 필드 | 의미 |
| --- | --- |
| `id` | 스킬 ID. 디렉터리 이름과 같아야 한다. |
| `source` | vendored snapshot을 가져온 canonical 원본 URL. |
| `source_ref` | 원본 commit, tag, release 또는 그에 준하는 갱신 기준점. |
| `license` | 재배포 가능한 라이선스 식별자 또는 함께 포함한 라이선스 파일 경로. |
| `vendored_at` | snapshot을 PAH에 반영한 날짜. |
| `notes` | 갱신 또는 설치에 필요한 보충 설명. |

`gstack`의 원본과 라이선스는 구현 전에 확인해야 한다. 확인되지 않으면 실제 스킬 snapshot을 배포하지 않는다.

## Installer 동작

`.devcontainer/ai-skills/install-ai-skills.sh`는 다음을 만족해야 한다.

- `/home/vscode/.local/share/pah/ai-skills/`에 설치한다.
- 여러 번 실행해도 안전해야 한다.
- 이미 설치된 버전이 scaffold 버전과 같으면 작업을 건너뛴다.
- 최종 스킬 디렉터리를 교체하기 전에 임시 디렉터리에 먼저 복사한다.
- 실패한 스킬과 단계를 알 수 있는 명확한 오류를 출력한다.
- 로그인 토큰, 대화 내역, AI 설정을 저장하지 않는다.

`templates/devcontainer/commands/post-create.sh`는 다음 명령을 호출해야 한다.

```bash
bash .devcontainer/ai-skills/install-ai-skills.sh
```

## AI 연결

### Codex

`pah install <target> --components devcontainer`는 `AGENTS.md`에 다음 managed block을 병합해야 한다.

```text
<!-- pah:devcontainer-ai-skills:start -->
When working inside the PAH devcontainer, read:
- /home/vscode/.local/share/pah/ai-skills/superpowers/SKILL.md
- /home/vscode/.local/share/pah/ai-skills/gstack/SKILL.md
<!-- pah:devcontainer-ai-skills:end -->
```

Codex native plugin 또는 skill 디렉터리 설치는 1차 구현 범위에서 제외한다.

### Claude

`pah install <target> --components devcontainer`는 `CLAUDE.md`에도 같은 의미의 managed block을 병합해야 한다.

Claude Code native skill 디렉터리 설치는 1차 구현 범위에서 제외한다.

### Cursor

`pah install <target> --components devcontainer`는 다음 파일을 설치해야 한다.

```text
.cursor/rules/gstack-skill.mdc
```

이 rule은 `gstack`의 짧은 설명을 담고 다음 경로를 가리켜야 한다.

```text
/home/vscode/.local/share/pah/ai-skills/gstack/SKILL.md
```

PAH는 `.cursor/rules/superpowers-skill.mdc`를 만들면 안 된다.

## Managed Block

Codex와 Claude는 하나의 devcontainer AI skill block을 사용한다.

```text
<!-- pah:devcontainer-ai-skills:start -->
...
<!-- pah:devcontainer-ai-skills:end -->
```

설치기는 managed block 밖의 내용을 보존해야 한다. 대상 파일에 손상되었거나 중복된 `pah:devcontainer-ai-skills` marker가 있으면 파일을 쓰기 전에 실패해야 한다.

## Manifest

`.harness/manifest.json`은 대상 프로젝트 파일만 기록한다. 컨테이너 내부 `/home/vscode/...` 경로는 기록하지 않는다.

`devcontainer` 컴포넌트가 설치되면 devcontainer AI skill scaffold 파일은 기존 `devcontainer` manifest 섹션에 포함한다. 별도의 `skills` manifest 섹션은 만들지 않는다.

포함할 파일은 다음과 같다.

```text
.devcontainer/ai-skills/install-ai-skills.sh
.devcontainer/ai-skills/skills-manifest.json
.devcontainer/ai-skills/superpowers/README.md
.devcontainer/ai-skills/superpowers/SKILL.md
.devcontainer/ai-skills/superpowers/metadata.json
.devcontainer/ai-skills/gstack/README.md
.devcontainer/ai-skills/gstack/SKILL.md
.devcontainer/ai-skills/gstack/metadata.json
.cursor/rules/gstack-skill.mdc
```

## 검증

`pah verify`는 manifest에 devcontainer 산출물이 있을 때만 devcontainer AI skill scaffold 파일을 검증한다.

필수 검증 항목:

- `.devcontainer/ai-skills/install-ai-skills.sh`가 존재하고 실행 가능하다.
- `.devcontainer/ai-skills/skills-manifest.json`이 존재한다.
- 각 스킬에 `README.md`, `SKILL.md`, `metadata.json`이 있다.
- 각 `metadata.json`에 `id`, `source`, `source_ref`, `license`, `vendored_at`이 있다.
- `AGENTS.md`와 `CLAUDE.md`에 예상한 `pah:devcontainer-ai-skills` managed block이 있다.
- `.cursor/rules/gstack-skill.mdc`가 존재하고 `/home/vscode/.local/share/pah/ai-skills/gstack/SKILL.md`를 참조한다.
- `.cursor/rules/superpowers-skill.mdc`가 존재하지 않는다.
- manifest hash가 실제 scaffold 파일과 일치한다.

컨테이너 내부 설치 결과는 기본 `pah verify`가 아니라 devcontainer smoke command로 검증한다.

```bash
bash .devcontainer/ai-skills/install-ai-skills.sh
test -f /home/vscode/.local/share/pah/ai-skills/superpowers/SKILL.md
test -f /home/vscode/.local/share/pah/ai-skills/gstack/SKILL.md
```

## 테스트 계획

`tests/test_pah.sh`에 다음 검증을 추가한다.

- `pah install <target> --components devcontainer`가 `.devcontainer/ai-skills/`를 생성한다.
- `install-ai-skills.sh`가 실행 가능하다.
- `superpowers`, `gstack` scaffold 파일에 `README.md`, `SKILL.md`, `metadata.json`이 포함된다.
- 필수 metadata 필드가 누락되면 install 또는 verify가 실패한다.
- `post-create.sh`가 `install-ai-skills.sh`를 호출한다.
- `AGENTS.md`, `CLAUDE.md`에 devcontainer AI skill managed block이 생성된다.
- `.cursor/rules/gstack-skill.mdc`가 생성된다.
- `.cursor/rules/superpowers-skill.mdc`는 생성되지 않는다.
- 유효한 devcontainer AI skill scaffold에서 `pah verify <target>`가 통과한다.
- `pah install <target> --components devcontainer`를 재실행해도 managed block이 중복되지 않는다.
- 손상된 `pah:devcontainer-ai-skills` marker가 있으면 사용자 내용을 덮어쓰지 않고 install이 실패한다.
- `pah install <target> --components rules,hooks`는 `.devcontainer/ai-skills/`를 만들지 않는다.
- `npm install` 또는 패키지 다운로드만으로 대상 프로젝트 파일이 생성되지 않는다.

## 구현 순서

1. `templates/devcontainer/ai-skills/`를 추가한다.
2. `superpowers`, `gstack` vendored snapshot을 `README.md`, `SKILL.md`, `metadata.json`과 함께 추가한다.
3. `templates/devcontainer/ai-skills/install-ai-skills.sh`를 추가한다.
4. `templates/devcontainer/commands/post-create.sh`가 installer를 실행하도록 수정한다.
5. Codex와 Claude용 devcontainer AI skill managed block stub을 추가한다.
6. Cursor용 `gstack-skill.mdc` stub을 추가한다.
7. `bin/pah`의 devcontainer 설치 흐름이 AI skill scaffold를 복사하고, managed block을 병합하고, Cursor rule을 설치하도록 수정한다.
8. `pah verify`에 devcontainer AI skill scaffold 검증을 추가한다.
9. `tests/test_pah.sh`에 실패 테스트를 먼저 추가한 뒤 통과하도록 구현한다.
10. `docs/usage.md`, `docs/reference.md`, `docs/how-it-works.md`를 갱신한다.
11. `bash tests/test_pah.sh`와 `git diff --check`를 실행한다.

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 스킬과 규칙 도메인의 책임이 섞임 | `skills` 컴포넌트를 추가하지 않고 스킬을 devcontainer scaffold 안에 둔다. |
| 컨테이너 내부 파일을 manifest에 잘못 기록함 | 대상 프로젝트 scaffold 파일만 기록하고 컨테이너 내부는 smoke command로 확인한다. |
| rebuild 후 스킬이 사라짐 | `post-create.sh`에서 idempotent installer를 다시 실행한다. |
| AI state와 스킬 파일이 섞임 | 로그인/설정 state는 named volume에 두고, 스킬은 재생성 가능한 bootstrap 산출물로 둔다. |
| Cursor가 과도한 컨텍스트를 읽음 | Cursor에는 `gstack`만 연결하고 rule을 짧게 유지한다. |
| vendored snapshot이 upstream과 달라짐 | metadata에 source/ref/license/vendored_at을 기록하고 명시적인 커밋으로 갱신한다. |
| 기존 프로젝트에 예상치 못한 파일이 생김 | `devcontainer` 컴포넌트를 설치할 때만 AI skill scaffold를 생성한다. |
