## 접근법 비교

### A. 외부 고정 위치 (PAH_HOME)

```bash
git clone <url> ~/.local/share/personal-agent-harness
~/.local/share/personal-agent-harness/bootstrap.sh <target>
```

| 장점 | 단점 |
|------|------|
| 즉시 적용 가능, 코드 변경 최소 | 경로 기억, 명령어 김 |
| 여러 프로젝트 공유 | “첫 설정”이 두 단계 |

### B. Ephemeral clone (설치 후 삭제)

```bash
git clone --depth 1 <url> /tmp/pah && /tmp/pah/setup.sh . && rm -rf /tmp/pah
```

| 장점 | 단점 |
|------|------|
| 프로젝트에 흔적 없음 | 매 업데이트마다 clone |

### C. 하네스 쪽 워크플로우 개선 (채택)

- `bootstrap.sh`, 문서 개편, `gitignore`에 `Personal-Agent-Harness/`
- `pah status --harness-root`로 버전 비교
- legacy in-project clone → `--clean-nested` 마이그레이션

**이후 확장:** 업계 1위 패턴인 **npm/npx CLI**로 배포 채널 변경

## 업계 패턴 조사 결과 (요약)

| 프로젝트 | Stars (대략) | 배포 방식 |
|----------|--------------|-----------|
| obra/superpowers | ~222k | IDE 플러그인 마켓 |
| github/spec-kit | ~111k | uv/uvx CLI → 프로젝트에 스캐폴드 |
| Fission-AI/OpenSpec | ~54k | `npm i -g` → `openspec init` |
| shadcn/ui | 광범위 | `npx shadcn add` → 소스 copy |
| madebywild/agent-harness | 소규모 | `npm i -D` + `npx harness init` |

**공통점:** 규칙/설정은 **프로젝트에 복사·커밋**, 도구는 **CLI(npm/npx)**.  
**node_modules에 규칙 본문을 넣는 패턴은 거의 없음.**

## 최종 아키텍처 결정

```text
npm 패키지 (personal-agent-harness)
  bin/pah-entry → bin/pah
        │
        │ pah init / pah update
        ▼
target-project/
  docs/, .cursor/rules/, AGENTS.md, .harness/manifest.json
  (Personal-Agent-Harness/ 없음)
```

| 항목 | 결정 |
|------|------|
| copy mode | 유지 |
| harness 소스 위치 | npm tarball / global install (프로젝트 밖) |
| 버전 추적 | manifest `harness_version` + `pah status` |
| git pull | git checkout 개발용만; npm 배포는 `npx @latest update` |
| 패키지 이름 | `personal-agent-harness` (unscoped, public) |
| 비용 | public npm → **$0** |
