## P0 — 배포 완료에 필수

### 1. 미커밋 변경사항 커밋

현재 `feat/external-harness-workflow`에 npm 관련 변경과 devcontainer 관련 변경이 unstaged 상태다. 두 흐름은 관련은 있지만 성격이 다르므로 커밋을 나누는 것을 권장한다.

```bash
cd ~/gw-personal/Personal-Agent-Harness

# 1) npm CLI 배포 전환
git add package.json bin/pah-entry bin/pah bootstrap.sh update.sh \
  tests/test_pah.sh README.md docs/usage.md docs/reference.md \
  docs/development.md .gitignore etc/
git commit -m "feat: add npm package and pah init/update commands"

# 2) 하네스 저장소 개발용 devcontainer
git add .devcontainer docs/superpowers/specs/2026-06-09-harness-devcontainer-design.md
git commit -m "chore: add harness development devcontainer"

# 3) 대상 프로젝트에 설치되는 devcontainer 템플릿 변경
git add templates/devcontainer
git commit -m "fix: align generated devcontainer with Node 24 image"
```

커밋 메시지·분할은 사용자 선호에 맞게 조정한다. 특히 `templates/devcontainer/`는 루트 `.devcontainer/`와 달리 대상 프로젝트 산출물을 바꾸므로 별도 커밋이 안전하다.

### 2. `npm publish` (사용자 직접)

- `command -v npm`으로 Linux npm인지 확인 후 실행
- Windows npm이 잡히는 WSL 환경에서는 WSL 경로의 `package.json`을 읽지 못할 수 있음
- 2FA OTP 입력 필요

```bash
cd ~/gw-personal/Personal-Agent-Harness
command -v npm
npm whoami
npm pack
npm publish
```

### 3. publish 후 스모크 테스트

```bash
mkdir -p /tmp/pah-npm-demo && cd /tmp/pah-npm-demo
npx personal-agent-harness init .
test ! -d Personal-Agent-Harness
npx personal-agent-harness verify .
npx personal-agent-harness status .
```

### 4. `main` 브랜치 머지

- PR 생성 또는 로컬 merge
- `feat/external-harness-workflow` → `main`

## P2 — UX 개선 (선택)

### 8. 셸 alias 가이드

`~/.bashrc`:

```bash
alias pah-init='npx personal-agent-harness init'
alias pah-up='npx personal-agent-harness@latest update'
```

### 9. GitHub Actions release workflow

- tag push → `npm test` + `npm publish`
- `NPM_TOKEN` 시크릿

### 10. `pah status` 개선

- publish된 npm 최신 버전과 비교 (`npm view personal-agent-harness version`)
- 네트워크 필요, 오프라인 fallback

### 11. devDependency 워크플로우

Node 프로젝트용:

```json
"devDependencies": { "personal-agent-harness": "0.3.0" },
"scripts": { "harness:init": "pah init ." }
```

문서화만으로도 가능.
